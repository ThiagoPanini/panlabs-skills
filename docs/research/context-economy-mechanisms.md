# Mecanismos do Claude Code para manter a janela de contexto enxuta

> Pesquisa de fundação sobre **o que o Claude Code oferece para que uma sessão de implementação carregue pouco, e o que a documentação oficial diz de cada mecanismo**. Toda linha abaixo rastreia a uma página primária que eu efetivamente abri — a documentação em `code.claude.com/docs` (baixada como `.md` bruto, o mesmo texto da página renderizada) e o changelog público. Nenhuma fonte secundária. Onde a doc não diz, digo isso na seção **Lacunas** em vez de arredondar.
>
> Data da pesquisa: 2026-09-12. Claude Code local: `2.1.269`. Citações em inglês são texto literal da página; o resto é leitura minha.
>
> **O retrato da árvore citado abaixo é o do dia da pesquisa, antes do [#247](https://github.com/ThiagoPanini/panlabs-skills/issues/247) aterrissar.** Foi o #247 que, a partir do que esta pesquisa confirmou, reescreveu o `CLAUDE.md` como mapa por seção, criou `.claude/rules/` com `paths:` para `skills/**` e `workbench/**/tests/**`, e escreveu `.claude/context-economy-protocol.md` — o marker que liga os dois hooks que já moravam em `~/.claude/hooks/`, fora deste repositório, e que sem ele saem calados. As frases «não há `.claude/rules/`» e «não há hooks» ficam como estavam, porque reescrever o registro para combinar com a árvore de hoje é falsificá-lo.

## 0. Como ler este documento

Uma seção H2 por mecanismo, na ordem em que o pedido os enumerou. Cada seção diz o que a doc afirma (com frase exata entre aspas), a URL da página que **possui** a afirmação, e fecha com uma linha **"O que isso muda para este repo"** — a régua é o estado real da árvore hoje: `CLAUDE.md` com 56 linhas e 5,1 KB, sem `.claude/rules/`, sem hooks, sem `.mcp.json`, três skills (`SKILL.md` de 183, 310 e 154 linhas; `description` de 383, 627 e 517 caracteres), e cinco arquivos em `docs/agents/` somando 424 linhas e 40 KB que o `CLAUDE.md` **linka** em vez de importar.

Um retrato útil antes das seções: a página [Explore the context window](https://code.claude.com/docs/en/context-window) resume o que entra antes do primeiro prompt — *"CLAUDE.md, auto memory, MCP tool names, and skill descriptions all load into context"* — e a tabela [Context cost by feature](https://code.claude.com/docs/en/features-overview#understand-context-costs) classifica: CLAUDE.md custa *"Every request"*; skills *"Low (descriptions every request)"*; MCP *"Low until a tool is used"*; subagentes *"Isolated from main session"*; hooks *"Zero, unless hook returns additional context"*.

## 1. `CLAUDE.md` — tamanho, imports `@path`, e o que `/doctor` e `/memory` dizem

**Tamanho.** A frase pedida existe, literal, em https://code.claude.com/docs/en/memory#write-effective-instructions: *"**Size**: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence."* A mesma página repete na seção de troubleshooting ([My CLAUDE.md is too large](https://code.claude.com/docs/en/memory#my-claude-md-is-too-large)): *"Files over 200 lines consume more context and may reduce adherence. Claude Code skips a file over 4 MiB."* O teto duro é só o de 4 MiB (*"loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file"*); 200 linhas é alvo, não corte.

**Como carrega.** *"CLAUDE.md content is delivered as a user message after the system prompt, not as part of the system prompt itself"* ([Troubleshoot](https://code.claude.com/docs/en/memory#claude-isnt-following-my-claude-md)). Arquivos do diretório atual e de todos os ancestrais carregam no arranque; *"Files in subdirectories load on demand when Claude reads files in those directories"* ([How CLAUDE.md files load](https://code.claude.com/docs/en/memory#how-claude-md-files-load)). Comentários HTML de bloco são removidos antes da injeção: *"Use them to leave notes for human maintainers without spending context tokens on them."*

**Imports `@path` — são eager.** *"Imported files are expanded and loaded into context at launch alongside the CLAUDE.md that references them."* Profundidade máxima de quatro saltos; *"Import parsing skips Markdown code spans and fenced code blocks"* — `@README` entre crases é literal ([Import additional files](https://code.claude.com/docs/en/memory#import-additional-files)). A doc é explícita que import não economiza: *"Splitting into `@path` imports helps organization but doesn't reduce context, since imported files load at launch."* Import que resolve fora do diretório de trabalho abre um diálogo de aprovação na primeira vez.

**O que entra e o que sai.** [When to add to CLAUDE.md](https://code.claude.com/docs/en/memory#when-to-add-to-claude-md): *"Keep it to facts Claude should hold in every session: build commands, conventions, project layout, "always do X" rules. If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule instead."* O `/doctor` (skill embutida desde a v2.1.205) *"proposes trims for a checked-in CLAUDE.md: it cuts content Claude can derive from the codebase, such as directory layouts, dependency lists, and architecture overviews, and keeps pitfalls, rationale, and conventions that differ from tool defaults. The trim check requires Claude Code v2.1.206 or later."* A [tabela de comandos](https://code.claude.com/docs/en/commands#all-commands) acrescenta que ele *"migrates the always-loaded guidance that remains into skills and nested `CLAUDE.md` files that load on demand"* e *"Reports findings first and asks for confirmation before changing anything."* Já o `/memory` não mede nada: *"lists your CLAUDE.md, CLAUDE.local.md, and other memory file locations"* e abre no editor; *"To check which files actually loaded into the current session, run `/context`."* ([View and edit with /memory](https://code.claude.com/docs/en/memory#view-and-edit-with-%2Fmemory)).

**Auto memory** (o outro arquivo carregado sempre): *"The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded at the start of every conversation"*; os arquivos de tópico não carregam no arranque ([How it works](https://code.claude.com/docs/en/memory#how-it-works)).

**O que isso muda para este repo:** o `CLAUDE.md` está em 56 linhas — bem abaixo do alvo — e a forma atual (linkar `docs/agents/*.md` em vez de `@`-importar) é exatamente a que a doc recomenda: converter os cinco links em imports colocaria 40 KB em toda sessão sem melhorar aderência. O único `@` no arquivo (`@me`, na linha 25) está entre crases, logo não é import. A dívida que a própria doc apontaria: a seção "Sessões paralelas" é procedimento de vários passos, e o `/doctor` proporia migrá-la para skill ou nested `CLAUDE.md`.

## 2. `.claude/rules/*.md` com `paths:` — glob, gatilho, versão, aninhamento

**Sem `paths:` carrega sempre.** *"Rules without `paths` frontmatter are loaded at launch with the same priority as `.claude/CLAUDE.md`."* e *"Rules without a `paths` field are loaded unconditionally and apply to all files."* ([Set up rules](https://code.claude.com/docs/en/memory#set-up-rules), [Path-specific rules](https://code.claude.com/docs/en/memory#path-specific-rules)). A doc avisa que rules não são o mecanismo de carga tardia por tarefa: *"Rules load into context every session or when matching files are opened. For task-specific instructions that don't need to be in context all the time, use skills instead."*

**Gatilho.** *"Path-scoped rules trigger when Claude reads files matching the pattern, not on every tool use."* A página [Explore the .claude directory](https://code.claude.com/docs/en/claude-directory) grafa como *"Rules with `paths:` load when a matching file enters context"*. O hook [`InstructionsLoaded`](https://code.claude.com/docs/en/hooks#instructionsloaded) (v2.1.69) expõe o gatilho: `load_reason` vale `session_start`, `nested_traversal`, `path_glob_match`, `include` ou `compact`, e `trigger_file_path` é *"Path to the file whose access triggered this load"*. Não há menção a disparo por simples citação do caminho no prompt — só por acesso ao arquivo.

**Glob.** Tabela na doc: `**/*.ts` (*"All TypeScript files in any directory"*), `src/**/*`, `*.md` (*"Markdown files in the project root"*), `src/components/*.tsx`. Aceita lista YAML ou string separada por vírgula (a lista YAML é da v2.1.84, changelog: *"Rules and skills `paths:` frontmatter now accepts a YAML list of globs"*). Expansão de chaves tem orçamento: *"a rule's whole `paths` list shares one budget of 1,000 expanded patterns and 4 MiB"*; `[` sem fechar invalida só aquele padrão.

**Aninhamento e escopo.** *"All `.md` files are discovered recursively, so you can organize rules into subdirectories like `frontend/` or `backend/`."* Há `~/.claude/rules/` (*"loaded before project rules, giving project rules higher priority"*) e symlinks com regra própria de aprovação. Rules com `paths:` **não sobrevivem ao `/compact`** por si: *"If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md"* ([What survives compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction)).

**Versão mínima.** Changelog `2.0.64`: *"Added support for .claude/rules/"* (https://code.claude.com/docs/en/changelog). Antes da v2.1.211, rules sob demanda carregavam mesmo com `project` excluído de `--setting-sources`.

**O que isso muda para este repo:** não há `.claude/rules/`. O candidato natural é `docs/agents/skills.md` (o que se espera antes de escrever sob `skills/`) como rule com `paths: ["skills/**"]` — carregaria só quando o agente tocasse uma skill, e zero nas sessões de docs. O custo a lembrar: rule com `paths:` some no `/compact` até o próximo acesso a um arquivo casado.

## 3. Hooks — `UserPromptSubmit`, `PreToolUse` com exit 2, `SessionStart`, e a forma do JSON

**Exit 0 e stdout.** [Exit code 0](https://code.claude.com/docs/en/hooks#exit-code-0): *"For most events, Claude Code writes stdout to the debug log and doesn't show it in the transcript. The exceptions are `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, and `PostModelSwitch`, where Claude Code adds plain-text stdout as context that Claude can see and act on."* Para `UserPromptSubmit`, a doc detalha os dois canais: *"Plain stdout and the `additionalContext` value are each injected as a system reminder that starts with the hook's name; Claude reads both."* e *"Neither channel produces a visible transcript entry."* O hook *"can't replace the prompt; it only injects `additionalContext` alongside it"*; `decision: "block"` *"prevents the prompt from being processed and erases it from context"*.

**Exit 2.** *"Exit 2 means a blocking error. On events that can block, exit 2 blocks whether or not you print JSON: even a JSON `permissionDecision` of `"allow"` can't override it."* Em `PreToolUse` *"blocks the tool call"* e *"Claude sees the stderr message as the denial reason"*; exit 1 é *"a non-blocking error"* e a ação prossegue ([Exit code 2](https://code.claude.com/docs/en/hooks#exit-code-2), [PreToolUse decision control](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)). Em `SessionStart`, exit 2 *"Shows stderr to user only"* — não bloqueia nada.

**`SessionStart`.** Matcher em `source`: `startup`, `resume`, `clear`, `compact`, `fork` (*"Before v2.1.214, forked sessions reported source "resume""*). Só `type: "command"` e `type: "mcp_tool"`. Campos de saída: `additionalContext` (*"String added to Claude's context at the start of the conversation, before the first prompt"*), `initialUserMessage`, `sessionTitle`, `reloadSkills`. A própria doc desaconselha usá-lo para texto fixo: *"For static context that doesn't require a script, use CLAUDE.md instead."* ([SessionStart](https://code.claude.com/docs/en/hooks#sessionstart)). O guia mostra o uso com `matcher: "compact"` para *"re-inject critical context after every compaction"*, e confirma: *"Claude Code adds plain text your command writes to stdout to Claude's context."* ([Re-inject context after compaction](https://code.claude.com/docs/en/hooks-guide#re-inject-context-after-compaction)).

**Forma do JSON (estável hoje).** *"`hookSpecificOutput` is a nested object for events that need richer control. It requires a `hookEventName` field set to the event name."* `additionalContext` vai dentro dele: *"Claude Code wraps the string in a system reminder and inserts it into the conversation at the point where the hook fired."* `PreToolUse` migrou: *"PreToolUse previously used top-level `decision` and `reason` fields, but these are deprecated for this event. Use `hookSpecificOutput.permissionDecision` and `hookSpecificOutput.permissionDecisionReason` instead."* Precedência entre hooks: `deny` > `defer` > `ask` > `allow`. Teto: *"Hook output strings, including `additionalContext`, `systemMessage`, and plain stdout, are capped at 10,000 characters"* — acima disso vira arquivo mais prévia ([JSON output](https://code.claude.com/docs/en/hooks#json-output), [Add context for Claude](https://code.claude.com/docs/en/hooks#add-context-for-claude)). Contexto injetado por hook *"Summarized with the rest of the conversation"* no `/compact`.

**O que isso muda para este repo:** não há hooks, e é a única forma **imposta** (não lida) de fazer valer regra do `CLAUDE.md` — a doc de memória é direta: *"To block an action regardless of what Claude decides, use a PreToolUse hook instead."* A regra "a `main` local nunca recebe commit" é candidata a `PreToolUse` com exit 2 sobre `git commit` na `main`. Custo de contexto: zero enquanto o hook não devolver `additionalContext`.

## 4. Subagentes — o que cruza para o pai, `Explore`, `context: fork`, `model` e `tools`

**Só o relatório final cruza.** [Create custom subagents](https://code.claude.com/docs/en/sub-agents): *"the subagent does that work in its own context and returns only the summary"*; *"Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions."* A simulação afirma o mesmo com número: *"Only the subagent's final text response comes back to your context, plus a small metadata trailer with token counts and duration. The subagent read 6,100 tokens of files. You got a 420-token result."* ([context-window](https://code.claude.com/docs/en/context-window)). E [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works#manage-context-with-skills-and-subagents): *"the subagent's tool calls stay out of your context, and Claude gets back a summary when the subagent finishes."* Ressalva da própria doc: *"Running many subagents that each return detailed results can consume significant context."*

**O que o subagente recebe.** [What loads at startup](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup): system prompt próprio (*"not the Claude Code system prompt"*), a mensagem de delegação, toda a hierarquia de `CLAUDE.md` e rules, git status, skills pré-carregadas via `skills`; **não** recebe histórico, skills já invocadas, arquivos já lidos, nem auto memory. Fork é a exceção: *"inherits the entire conversation so far"*, e ainda assim *"The fork's own tool calls still stay out of your conversation and only its final result comes back"*.

**`Explore`.** *"A fast, read-only agent optimized for searching and analyzing codebases."* *"Tools: read-only tools; Write and Edit are denied."* *"Explore and Plan skip your CLAUDE.md files and the parent session's git status to keep research fast and inexpensive."* Modelo: *"inherits from the main conversation, capped at Opus on the Claude API"* (desde a v2.1.198; antes rodava sempre em Haiku). Níveis de profundidade: `quick`, `medium`, `very thorough`. Descrições de subagentes custom pesam: aviso no arranque quando *"exceed 15,000 tokens"*.

**Frontmatter.** `tools`: *"Inherits every tool available to subagents if omitted"*. `model`: *"`sonnet`, `opus`, `haiku`, `fable`, a full model ID such as `claude-opus-5`, or `inherit`"*. `skills`: *"The full skill content is injected, not only the description."* `mcpServers` inline: *"To keep an MCP server out of the main conversation entirely and avoid its tool descriptions consuming context there, define it inline here rather than in `.mcp.json`."* ([Supported frontmatter fields](https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields)).

**`context: fork` em skills — existe.** *"Add `context: fork` to your frontmatter when you want a skill to run in isolation. Claude Code starts a new subagent of the type set in the `agent` field and gives it the skill content as its prompt. The subagent doesn't see your conversation history"*. Aviso de nome: *"Despite the name, a skill with `context: fork` doesn't run in a fork of the current conversation"*. Introduzido na v2.1.0; roda em background por padrão desde a v2.1.218 (`background: false` para esperar) ([Run skills in a subagent](https://code.claude.com/docs/en/skills#run-skills-in-a-subagent)).

**O que isso muda para este repo:** a memória "suíte de render morre de OOM com subagente" e "sub-agente de revisão muta a árvore" já são o outro lado desta moeda — o isolamento é de **contexto**, não de disco nem de RAM. Para revisão e pesquisa, `Explore` é o mais barato (sem `CLAUDE.md`, sem git status, read-only). Para uma skill de pesquisa como esta `/research`, `context: fork` com `agent: Explore` é a forma documentada de não trazer o material lido para o pai.

## 5. Skills — o que carrega sempre, na ativação, e por referência; limite da `description`; `disable-model-invocation`

**Três camadas.** [Extend Claude with skills](https://code.claude.com/docs/en/skills): *"Unlike CLAUDE.md content, a skill's body loads only when it's used, so long reference material costs almost nothing until you need it."* A tabela de invocação grafa a camada 1 e 2: padrão = *"Description always in context, full skill loads when invoked"*. A camada 3 é a árvore de apoio: *"reference.md (detailed API docs - loaded when needed)"*, *"helper.py (utility script - executed, not loaded)"*, com o conselho *"Keep `SKILL.md` under 500 lines. Move detailed reference material to separate files."* ([Add supporting files](https://code.claude.com/docs/en/skills#add-supporting-files)).

**O que a listagem custa.** *"Every skill in the skill listing adds to your context on every turn, whether or not Claude ever uses it."* [Skill descriptions are cut short](https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short): *"the combined `description` and `when_to_use` text is truncated at 1,536 characters in the skill listing"* (`skillListingMaxDescChars`, default `1536`); *"The budget scales at 1% of the model's context window"* (`skillListingBudgetFraction`, default `0.01`); ao estourar, *"drops descriptions starting with the skills you invoke least"*. *"Run `/doctor` for an estimate of the listing's context cost and its biggest contributors."* *"The Skills row in `/context` reports the size of the listing after the budget is applied"* (v2.1.196). `/skill-doctor` agora é público: *"to see what each of your skills costs and how often it gets used"* — a nota anterior deste repo o tinha como não confirmado.

**Depois de ativar.** [Skill content lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle): *"the rendered `SKILL.md` content enters the conversation as a single message and stays there across later turns"*; reinvocar com conteúdo idêntico acrescenta *"a short note that the skill is already loaded rather than a second copy"*. No `/compact`: *"keeping the first 5,000 tokens of each. Re-attached skills share a combined budget of 25,000 tokens"*. Daí o conselho: *"Keep the body itself concise. Once a skill loads, its content stays in context across turns, so every line is a recurring token cost."* A listagem em si **não** volta após `/compact` (*"this listing is not re-injected after `/compact`"*, context-window).

**`disable-model-invocation: true`.** *"Description not in context, full skill loads when you invoke"*; *"This removes the skill from Claude's context entirely"*; também *"prevents the skill from being preloaded into subagents"*. Skills têm `paths:` também: *"Claude loads the skill automatically only when working with files matching the patterns"* ([Frontmatter reference](https://code.claude.com/docs/en/skills#frontmatter-reference)).

**O que isso muda para este repo:** as três `description` (383, 627, 517 caracteres) cabem no teto de 1.536, e os três `SKILL.md` ficam abaixo de 500 linhas — mas o corpo de 310 linhas da `panlabs-presentation-builder` é o que vira "custo recorrente por turno" depois de ativado, e após um `/compact` só os primeiros 5.000 tokens dele voltam; a doc manda pôr o essencial no topo. `scripts/check-skills.sh` já mede linhas e `description`; o que ainda não mede é o orçamento de 1% da listagem, que `/doctor` estima.

## 6. `/compact`, `/clear`, `/context`, 1M, limiares de auto-compact, `/usage`

**`/compact [instructions]`** — *"Free up context by summarizing the conversation so far. Optionally pass focus instructions for the summary."* ([Commands](https://code.claude.com/docs/en/commands#all-commands)). Instrução permanente no `CLAUDE.md`: [Manage costs](https://code.claude.com/docs/en/costs#reduce-token-usage) mostra o exemplo *"When you are using compact, please focus on test output and code changes"*, e [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up) chama isso de *"a "Compact Instructions" section to CLAUDE.md"*. Ordem do processo: *"It clears older tool outputs first, then summarizes the conversation if needed."* Custo: *"a mid-session `/compact` costs a fraction of what the context size suggests"* com cache quente, e *"`/compact` costs the most when you resume an old session"* ([Prompt caching](https://code.claude.com/docs/en/prompt-caching#compacting-the-conversation)). Editar `CLAUDE.md` no meio da sessão não aplica: *"The new content loads on the next `/clear`, `/compact`, or restart."* Compactação parcial existe via `/rewind` → *"Summarize from here"*.

**O que sobrevive** ([What survives compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction)): `CLAUDE.md` da raiz e rules sem `paths:` *"Re-injected from disk"*; nested `CLAUDE.md` e rules com `paths:` recarregam quando o arquivo casado é lido de novo; corpos de skills invocadas com o teto 5.000/25.000; contexto de hooks *"Summarized with the rest of the conversation"*; hooks `SessionStart` com `compact` rodam. Claude Code *"re-reads up to five of the files Claude has read or edited in the session"*; arquivo acima de 5.000 tokens *"comes back as a path reference without its content"*.

**`/clear [name]`** — *"Start a new conversation with empty context. ... To free up context while continuing the same conversation, use `/compact` instead."* Aliases `/reset`, `/new`. *"When you want a fresh start instead of continuity, `/clear` costs nothing"* (costs). [Best practices](https://code.claude.com/docs/en/best-practices): *"If you've corrected Claude more than twice on the same issue in one session, the context is cluttered with failed approaches. Run `/clear`"*. `/btw` responde *"a side question that shouldn't add to the conversation history"*.

**`/context [all]`** — *"Visualize current context usage as a colored grid. Shows optimization suggestions for context-heavy tools, memory bloat, and capacity warnings."* Em fullscreen colapsa o detalhe; `all` expande. A doc nomeia as linhas **Memory files** (para confirmar que o `CLAUDE.md` carregou), **Skills**, e no changelog **Messages** e **Free space**. Sugestões desde a v2.1.74; até a v2.1.129 o próprio grid caía na conversa (*"wasting ~1.6k tokens per call"*, corrigido).

**1M.** [Model configuration](https://code.claude.com/docs/en/model-config#extended-context): *"Fable 5.1, Fable 5, Sonnet 5, Opus 4.6 and later, and Sonnet 4.6 support a 1 million token context window"*; *"On the Anthropic API, Fable 5.1, Fable 5, Sonnet 5, and Opus 4.7 and later run with the 1M window by default"*; em Max/Team/Enterprise *"Opus is automatically upgraded to 1M context"*; Sonnet 4.6 1M exige usage credits. Seleção: `/model opus[1m]`, `sonnet[1m]`, ou sufixo `[1m]` no ID. Desligar: `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. *"no premium for tokens beyond 200K"*.

**Auto-compact.** [Default auto-compact thresholds](https://code.claude.com/docs/en/model-config#default-auto-compact-thresholds): *"If you don't set an auto-compact window, Claude Code compacts when the conversation reaches the model's context limit"*, com exceções — modelos com 1M nativo *"compact before the window fills, at about 967K tokens by default"*; Sonnet 4.6 / Opus 4.6 sem contexto estendido *"compact at the 200K boundary"*. Ajuste: `/autocompact 500k` (grava `autoCompactWindow`, 100K a 1M), flag `--autocompact`, ou `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (que vence os outros). Desligar: `autoCompactEnabled: false` ou `DISABLE_AUTO_COMPACT`; `/compact` manual continua funcionando. Se um único item enche a janela de novo após cada resumo, *"Claude Code stops auto-compacting after a few attempts and shows an error instead of looping"*.

**`/usage`, `/cost`, `/stats`.** *"`/usage` — Show session cost, plan usage limits, and activity stats"*; *"`/cost` — Alias for `/usage`"*; `/stats` idem, na aba Stats. Em planos de assinatura inclui *"Attribution: recent usage attributed to skills, subagents, plugins, and individual MCP servers"* e *"flags behaviors that account for 10% or more of your recent usage, such as long context or cache misses"* ([Manage costs](https://code.claude.com/docs/en/costs#plan-usage-breakdown)).

**O que isso muda para este repo:** o `CLAUDE.md` não tem seção de instruções de compactação; para tickets longos (a fila serial da presentation-builder), uma seção "Compact Instructions" pedindo para preservar número do ticket, território declarado e o estado da união é barata e documentada. Nas sessões sob Fable 5.1 a janela é 1M nativa e o auto-compact só dispara perto de 967K — o problema real deste repo não é estourar, é **diluir**: a doc diz *"LLM performance degrades as context fills"*, o que argumenta por `/clear` entre tickets, não por janela maior.

## 7. Baseline — schemas MCP, `ToolSearch`, `disabledMcpjsonServers`, e como medir

**Schemas MCP são adiados por padrão.** [Scale with MCP tool search](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search): *"Tool search keeps MCP context usage low by deferring tool definitions until Claude needs them. Only tool names and server instructions load at session start"*; *"Tool search is enabled by default: MCP tools are deferred and discovered on demand."* É desligado automaticamente quando `ANTHROPIC_BASE_URL` aponta para host não first-party. `ENABLE_TOOL_SEARCH`: `(unset)` = tudo adiado; `true`; `auto` = *"loads the tools it would otherwise defer upfront while their definitions total less than 10% of the context window"*; `auto:N`; `false` = tudo no arranque. Por servidor, `alwaysLoad: true` isenta do adiamento. *"Claude Code truncates tool descriptions and server instructions at 2KB each."* A ferramenta é [`ToolSearch`](https://code.claude.com/docs/en/tools-reference): *"Searches for and loads deferred tools when tool search is enabled"*; dá para negá-la em `permissions.deny`. Histórico: v2.1.7 ligou o modo `auto` por padrão (*"When MCP tool descriptions exceed 10% of the context window, they are automatically deferred"*); v2.1.9 trouxe `auto:N`. Saída de tool MCP: aviso acima de 10.000 tokens, limite de 25.000 (`MAX_MCP_OUTPUT_TOKENS`).

**`disabledMcpjsonServers`.** [All settings](https://code.claude.com/docs/en/settings-reference#disabledmcpjsonservers): *"Reject specific servers defined in a project's `.mcp.json` file so Claude Code never connects them or asks you to approve them. A rejection in any settings file applies, including a project `.claude/settings.json` checked into the repository."* *"Rejection takes precedence over `enabledMcpjsonServers` and `enableAllProjectMcpServers`."* Não confundir com `disabledMcpServers`, que é a lista de opt-out para servidores de usuário, plugin, managed e conectores claude.ai ([Disable a server without removing it](https://code.claude.com/docs/en/mcp#disable-a-server-without-removing-it)). Conselho da doc de custos: *"Tools like `gh`, `aws`, `gcloud`, and `sentry-cli` are still more context-efficient than MCP servers because they don't add any per-tool listing."*

**Medir o baseline.** O instrumento documentado é `/context` (seção 6). Para skills, `/doctor` e `/skill-doctor`; para instruções, o hook `InstructionsLoaded` *"to log exactly which instruction files are loaded, when they load, and why"*; para o custo por feature ao longo do tempo, a atribuição do `/usage` e a [status line](https://code.claude.com/docs/en/statusline). A simulação em [context-window](https://code.claude.com/docs/en/context-window) dá ordens de grandeza de um arranque típico — system prompt 4.200 tokens, environment 280, nomes MCP 120, descrições de skills 450, `~/.claude/CLAUDE.md` 320, `CLAUDE.md` do projeto 1.800, auto memory 680 — mas a própria página avisa: *"Token counts are illustrative. Actual values vary with your CLAUDE.md size, MCP servers, and file lengths."* Um detalhe de forma: *"Git branch, status, and recent commits load as a separate block at the very end of the system prompt"* (desligável com `includeGitInstructions`).

**O que isso muda para este repo:** sem `.mcp.json`, o baseline aqui é system prompt + `~/.claude/CLAUDE.md` + `CLAUDE.md` + auto memory (`MEMORY.md` tem 19 entradas, todas de uma linha, dentro do teto de 200 linhas) + a listagem das três skills. A alavanca real não é MCP; é a listagem de skills e o `MEMORY.md`, e o que uma sessão lê depois — daí subagente para pesquisa (seção 4).

## Lacunas

- **Gatilho de rule por escrita.** A doc só diz *"when Claude reads files matching the pattern"* e *"when a matching file enters context"*. Não achei frase dizendo se `Edit`/`Write` sem `Read` prévio dispara a rule. `trigger_file_path` fala em *"access"*, o que sugere que sim, mas não está escrito.
- **`@path` dentro de `.claude/rules/*.md`.** A página de memória descreve imports só para `CLAUDE.md`. O `load_reason: include` do `InstructionsLoaded` tem `parent_file_path` (*"the parent instruction file that included this one"*), sem dizer se um arquivo de rule pode ser pai. Não confirmado.
- **Versão em que o tool search passou de `auto` (10%) para "tudo adiado".** O changelog registra o `auto` por padrão na v2.1.7 e o `auto:N` na v2.1.9; a doc atual diz que `(unset)` adia tudo. Não localizei a entrada que fez essa troca.
- **Versão mínima do `paths:` em rules.** `.claude/rules/` é da v2.0.64 e a lista YAML da v2.1.84; se a forma string existia já na v2.0.64, o changelog não diz.
- **Linhas do `/context`.** A doc nomeia **Memory files**, **Skills**, **Messages** e **Free space**, mas nenhuma página enumera todas as linhas nem diz se há uma linha isolada para o system prompt. Não há comando documentado que imprima só o tamanho do system prompt.
- **`Explore` e o relatório.** A doc afirma o isolamento e o retorno só do resumo para subagentes em geral; não há frase específica sobre o formato ou o teto do relatório final do `Explore`.
- **Post "Prompt caching is everything".** A doc de caching linka o post do blog da Anthropic como fonte da lógica de adiamento e compactação; não o abri, e nada acima depende dele.
